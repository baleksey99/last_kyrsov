# Бэкенд-часть SPA-приложения «Трекер полезных привычек»

## 1. Обзор проекта
Данный проект представляет собой бэкенд-часть SPA-веб-приложения — трекера полезных привычек, вдохновлённого книгой Джеймса Клира «Атомные привычки». Цель — помочь пользователям формировать полезные привычки и отслеживать их выполнение с помощью напоминаний через Telegram.

## 2. Функциональность
Трекинг привычек (полезных и приятных).
Напоминания о выполнении привычек через Telegram.
Пагинация списка привычек (5 привычек на страницу).
Система авторизации/регистрации пользователей.
Управление привычками (CRUD-операции).
Публичные привычки — возможность делиться своими привычками с другими пользователями.
Отложенные задачи (напоминания) реализованы через Celery.
Интеграция с фронтендом через REST API.
## 3. Модели данных
Модель «Привычка» включает поля:
user — создатель привычки (ForeignKey);
place — место выполнения привычки (строка);
time — время выполнения привычки (время);
action — описание действия (строка);
is_pleasant — признак приятной привычки (булево);
related_habit — связанная привычка (ForeignKey, только для полезных привычек);
frequency — периодичность (число, по умолчанию — 1 (ежедневно));
reward — вознаграждение за выполнение (строка, только для полезных привычек);
duration — время на выполнение (число, ≤ 120 секунд);
is_public — признак публичности (булево).
## 4. Эндпоинты API
Метод	Путь	Описание
POST	/api/auth/register/	Регистрация пользователя
POST	/api/token/	Авторизация (получение JWT-токена)
GET	/api/habits/?user_id={id}	Список привычек текущего пользователя (с пагинацией)
GET	/api/habits/public/	Список публичных привычек
POST	/api/habits/	Создание привычки
PUT/ PATCH	/api/habits/{id}/	Редактирование привычки
DELETE	/api/habits/{id}/	Удаление привычки
## 5. Валидаторы
Нельзя одновременно заполнять поля reward и related_habit.
Время выполнения привычки ≤ 120 секунд.
В related_habit можно указывать только привычки с is_pleasant=True.
У приятной привычки не может быть reward или related_habit.
Периодичность выполнения привычки: минимум 1 раз в 7 дней.
Нельзя пропускать выполнение привычки более 7 дней.
## 6. Права доступа
Пользователи имеют доступ только к своим привычкам (CRUD).
Публичные привычки доступны только для чтения (без редактирования/удаления).
Суперпользователь имеет доступ ко всем привычкам.
## 7. Интеграция с Telegram
Реализована рассылка напоминаний о привычках.
Используется бот Telegram с настроенным токеном.
Уведомления отправляются в соответствии с периодичностью привычек.
## 8. Технологии и зависимости
Backend: Django, Django REST Framework.
База данных: PostgreSQL.
Аутентификация: JWT (Simple JWT).
Отложенные задачи: Celery + Redis (или RabbitMQ).
CORS: django-cors-headers.
Валидация: Django валидаторы, DRF serializers.
Тестирование: pytest, django-test.
Форматирование кода: black, isort, flake8.
Список всех зависимостей — в файле requirements.txt.
